# Full Lifecycle: Draft → Backlog → Doing → Done

## Job Story

**When** я веду задачу от идеи через исполнение до завершения,
**I want** чтобы все переходы Draft→Backlog→Doing→Done работали одним кликом каждый и timestamps писались корректно,
**so** у меня надёжная история работы и корректная аналитика эффорта.

## Preconditions

- Exocortex plugin ≥ v15.90.21
- Starter kit installed
- Fixture note: `Lifecycle Test Task.md` with:
  - `exo__Instance_class: [[ems__Task]]`
  - `ems__Effort_status: [[ems__EffortStatusDraft]]`
  - No existing `startTimestamp`, `endTimestamp`, or `resolutionTimestamp`
- Vault state = `seeded`

## Scenario: Complete lifecycle on one task

```gherkin
  Given I open "Lifecycle Test Task" in Reading Mode
  Then I see "Set Status Backlog" button
  And I do NOT see "Set Draft Status" button

  When I click "Set Status Backlog" button
  Then Task frontmatter has ems__Effort_status: [[ems__EffortStatusBacklog]]
  And "Set Status Backlog" button disappears
  And "Set Status Doing" button appears

  When I click "Set Status Doing" button
  Then Task frontmatter has ems__Effort_status: [[ems__EffortStatusDoing]]
  And Task frontmatter has ems__Effort_startTimestamp matching ISO-8601
  And "Set Status Doing" button disappears
  And "Set Status Done" button appears

  When I click "Set Status Done" button
  Then Task frontmatter has ems__Effort_status: [[ems__EffortStatusDone]]
  And Task frontmatter has ems__Effort_endTimestamp matching ISO-8601
  And Task frontmatter has ems__Effort_resolutionTimestamp matching ISO-8601
  And ems__Effort_endTimestamp == ems__Effort_resolutionTimestamp
  And "Set Status Done" button disappears
  And "Archive Completed" button appears

  Then Task frontmatter still has ems__Effort_startTimestamp from earlier step
  And Task frontmatter still has exo__Asset_createdAt from initial state
```

### User effort (hard assertions)

| Metric | Max | Measured how |

### Observable behavior (hard assertions)

- No modal, no toast, no `new Notice()` at any transition
- `exocortex-logs.txt` diff contains zero new `[ERROR]` lines
- All 3 transitions happen with single click each
- `exo__Asset_createdAt` preserved across all transitions
- `ems__Effort_startTimestamp` preserved across Doing → Done transition
- At Done state: both `endTimestamp` and `resolutionTimestamp` exist and equal
- Button visibility follows state machine (no stale buttons from previous states)

### Soft informational

- Wall-clock elapsed per transition — logged, not asserted

## Failure modes (documented)

- Forward-only rule broken (Doing → Backlog possible) → state machine regression
- Timestamp not preserved across transitions → FrontmatterService merge bug
- endTimestamp != resolutionTimestamp at Done → DoneTransition command bug
- Multiple buttons visible simultaneously (stale button) → ButtonVisibilityRule regression
- `exo__Asset_createdAt` lost or rewritten → YAML preservation bug
