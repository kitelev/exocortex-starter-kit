# Create Child Task from Parent

## Job Story

**When** я открываю существующий Project или Area и понимаю, что нужна новая подзадача,
**I want** одним жестом создать child Task с унаследованной parent-ссылкой,
**so** я не теряю контекст и не редактирую frontmatter руками.

## Preconditions

- Exocortex plugin ≥ v15.90.21 loaded
- Starter kit installed (`ems/` ontology resolved)
- Seeded notes in vault:
  - `Development.md` with `exo__Instance_class: [[ems__Area]]`
  - `Build API Server.md` with `exo__Instance_class: [[ems__Project]]` and `ems__Effort_area: [[Development]]`
- Vault state = `seeded` (Preconditions list seeded fixture notes; vault also requires starter-kit ontology to be present)

## Scenario A: Child task from Project

```gherkin
  Given I open "Build API Server" in Reading Mode
  Then I see a "Create Task" button above properties table
  When I click "Create Task" button
  Then a new Task note opens in a new leaf
  And the new Task frontmatter contains exo__Instance_class: [[ems__Task]]
  And the new Task frontmatter contains ems__Effort_parent: [[Build API Server]]
  And the new Task frontmatter contains ems__Effort_status: [[ems__EffortStatusDraft]]
  And the new Task frontmatter contains exo__Asset_uid matching UUID-v4 pattern
  And the new Task frontmatter contains exo__Asset_createdAt with ISO-8601 timestamp
```

## Scenario B: Child task from Area

```gherkin
  Given I open "Development" in Reading Mode
  Then I see a "Create Task" button above properties table
  When I click "Create Task" button
  Then a new Task note opens in a new leaf
  And the new Task frontmatter contains exo__Instance_class: [[ems__Task]]
  And the new Task frontmatter contains ems__Effort_area: [[Development]]
  And the new Task frontmatter contains ems__Effort_status: [[ems__EffortStatusDraft]]
```

## Acceptance Gates

### User effort (hard assertions)

| Metric | Max | Measured how |
|---|---|---|
| Clicks from idle to new Task open | 2 | action-log.jsonl counts `left_click` events |
| Keystrokes in ideal path | 0 | action-log.jsonl counts `type_text` events |

### Observable behavior (hard assertions)

- No modal, no toast, no `new Notice()` visible between trigger and result
- `exocortex-logs.txt` diff contains zero new `[ERROR]` lines
- New Task frontmatter shape matches all `Then`-assertions above
- All wikilinks in the new Task resolved (Reading Mode shows blue, not grey)
- New Task file placed in same folder as parent (matches BDD area-task-creation.feature)

### Soft informational (NOT a gate)

- Wall-clock elapsed time — logged in `timings.json`, never failure condition (computer-control screenshot overhead makes wall-clock unreliable as UX SLA)

## Failure modes (documented, not assertions)

- `Create Task` button missing from layout → regression of #2745 family or CommandVisibility rules
- Button visible but click creates Task with wrong parent property → grounding regression (see `ems__Effort_parent` vs `ems__Effort_area` distinction)
- UUID-only wikilink in new Task renders without rdf:type → #2745 variant
- Sync status modal covers layout before screenshot → known Obsidian pitfall (pre-close via computer-control)
