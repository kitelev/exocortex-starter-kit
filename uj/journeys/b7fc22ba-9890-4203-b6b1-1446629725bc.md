# Start Effort: Backlog → Doing

## Job Story

**When** я готов приступить к задаче из бэклога,
**I want** одним кликом перевести её в Doing и зафиксировать startTimestamp,
**so** я не редактирую frontmatter руками и не забываю когда начал.

## Preconditions

- Exocortex plugin ≥ v15.90.21
- Starter kit installed
- Fixture note: `Implement Feature.md` with:
  - `exo__Instance_class: [[ems__Task]]`
  - `ems__Effort_status: [[ems__EffortStatusBacklog]]`
  - No existing `ems__Effort_startTimestamp`
- Vault state = `seeded` (fixture seeded before run)

## Scenario A: Button is visible for Backlog tasks

```gherkin
  Given I open "Implement Feature" in Reading Mode
  Then I see a "Set Status Doing" button in the action button area
  And I do NOT see "Set Status Backlog" button
```

<!-- NB: Starter-kit v1.5.1 ships independent "Set Status X" commands, each
     guarded by a "Not in X status" precondition. In Backlog state only
     "Set Status Backlog" is hidden; "Set Status Done" et al. remain visible
     because their preconditions are satisfied (status != Done). Don't add
     "I do NOT see Set Status Done" — it's false and reports a phantom bug. -->


## Scenario B: Click transitions status and sets startTimestamp

```gherkin
  Given I open "Implement Feature" in Reading Mode
  When I click "Set Status Doing" button
  Then the Task frontmatter has ems__Effort_status: [[ems__EffortStatusDoing]]
  And the Task frontmatter has ems__Effort_startTimestamp matching ISO-8601 without milliseconds
  And the Task frontmatter has ems__Effort_startTimestamp within 10 seconds of current time
  And "Set Status Doing" button disappears from layout
  And "Set Status Backlog" button appears in the action button area
```

## Scenario C: Other frontmatter properties preserved

```gherkin
  Given "Implement Feature" has ems__Effort_area: [[Development]]
  And "Implement Feature" has exo__Asset_uid: <some-uuid>
  When I click "Set Status Doing" button
  Then the Task frontmatter still contains ems__Effort_area: [[Development]]
  And the Task frontmatter still contains exo__Asset_uid: <same-uuid>
```

### Observable behavior (hard assertions)

- `exocortex-logs.txt` diff contains zero new `[ERROR]` lines
- Frontmatter matches all `Then`-assertions
- startTimestamp format = `YYYY-MM-DDTHH:mm:ss` (no milliseconds, no timezone suffix)
- Other pre-existing frontmatter keys preserved (no data loss)

### Soft informational

- Wall-clock elapsed — logged, not asserted

## Failure modes (documented)

- Button invisible for a Backlog task → CommandVisibility regression or starter-kit status UUIDs drifted
- Click transitions status but no startTimestamp written → FrontmatterService write path regression
- startTimestamp written with milliseconds or timezone suffix → DateFormat helper regression
- Other frontmatter properties lost → YAML serialize bug
