# Create Area → Project → Task Hierarchy from Scratch

## Job Story

**When** я начинаю новый домен работы с нуля,
**I want** создать Area, внутри неё Project, внутри Project первую Task с корректно прокинутыми parent-ссылками,
**so** у меня готовая иерархия и starting point без ручного редактирования frontmatter.

## Preconditions

- Exocortex plugin ≥ v15.90.28
- Starter kit installed (onboarding state — equivalent to Getting Started Guide result)
- Vault state = `fresh` (no pre-existing Area/Project/Task notes, only starter-kit ontology)

## Scenario: Three-step hierarchy creation via dedicated commands

```gherkin
  Given the vault has no ems__Area, ems__Project, or ems__Task assets yet
  And starter-kit ontology files are present

  When I create note "Research" with Write tool containing frontmatter:
    | Key                 | Value                                              |
    | exo__Instance_class | [[82c74542-1b14-4217-b852-d84730484b25|ems__Area]] |
    | exo__Asset_label    | Research                                           |
  Then I open "Research" in Reading Mode
  And I see "Research" rendered with class badge "ems__Area"
  And I see "Create Project" button in the COMMANDS panel
  And I see "Create Child Task" button in the COMMANDS panel
  And I see empty Asset Relations section (no children yet)

  When I click "Create Project" button on "Research"
  And I type "Thesis Writing" in the Input required modal
  And I click OK to confirm
  Then a new Project "Thesis Writing" opens in a new leaf
  And "Thesis Writing" renders with class badge "ems__Project"
  And "Thesis Writing" has ems__Effort_area: [[Research]]
  And I open "Thesis Writing" in Reading Mode
  And I see "Create Child Task" button in the COMMANDS panel

  When I click "Create Child Task" button on "Thesis Writing"
  And I type "Draft outline" in the Input required modal
  And I click OK to confirm
  Then a new Task "Draft outline" opens in a new leaf
  And "Draft outline" renders with class badge "ems__Task"
  And "Draft outline" has ems__Effort_parent: [[Thesis Writing]]
  And "Draft outline" has ems__Effort_status: [[ems__EffortStatusDraft]]

  When I open "Research" in Reading Mode
  Then Asset Relations on "Research" shows "Thesis Writing" as child Project
  And Asset Relations on "Research" shows "Draft outline" as descendant Task (via Project hierarchy)
```

**Spec history**: an earlier revision of this journey expected the user to click `Create Task` on Area then manually flip `exo__Instance_class` from Task to Project. Starter-kit v1.5.1+ ships dedicated `Create Project` (on Area) and `Create Child Task` (on Project + Area) commands, eliminating the manual class flip and the file rename. The journey now exercises the dedicated path end-to-end.

### User effort (hard assertions)

> **Note on click budget**: each `Create *` command via `service_call` grounding opens an `Input required` modal. Obsidian does not bind Enter to its default OK action when driven via `computer-control` key-event injection (memory `feedback_obsidian_input_required_enter.md`), so each creation flow costs **2 clicks** (button + OK confirm). 3 creations × 2 clicks = 6.

### Observable behavior (hard assertions)

- No unexpected modal, no toast beyond the per-creation success notice
- `exocortex-logs.txt` diff contains zero new `[ERROR]` lines
- At each level (Area, Project, Task): class badge rendered blue (resolved), not grey
- Parent references propagate correctly: Project has `ems__Effort_area` to Area; Task has `ems__Effort_parent` to Project
- New Task carries `ems__Effort_status: [[ems__EffortStatusDraft]]` (default for `Create Child Task`)
- Asset Relations on Area shows Project as child
- Asset Relations on Area shows Task as descendant (via Project hierarchy display rules)

### Soft informational

- Wall-clock — logged, not asserted

## Failure modes (documented)

- Class badge grey → wikilink resolution broken (UUID-alias pattern #2745 regression)
- Asset Relations empty when children exist → AreaHierarchyTree regression
- Parent reference not written (Task has no `ems__Effort_parent`) → `inheritParentContext` regression in `GenericAssetCreationService`
- `[object Object]` rendered in parent cell → two-render-path regression (similar to plan-for-today issue)
- `Create Project` button missing on Area → command binding `e3a7c84b-0f70-4a1c-95da-c66bbb33dd5d` (or equivalent) missing or stale
- Task carries wrong `Effort_status` (e.g. `Backlog` instead of `Draft`) → `createRelatedTask` handler regression
