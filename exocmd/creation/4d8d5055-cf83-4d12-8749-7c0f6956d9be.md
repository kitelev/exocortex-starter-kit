# Create task for daily note (declarative)

Creates an `ems__Task` in the same folder as the host `period__DailyNote`.
Folder resolution uses the `$targetFolder` substitution token.

## History

- Issue #3136 (RFC `18407cb2-9554-4897-9213-17321f9dd434` Path B, Q3.b closure)
  — migrated from `service_call` + `serviceId: createTaskForDailyNote` to
  declarative `create_instance` once the `$targetFolder` substitution token
  and the legacy `exocmd__Grounding_propertyDefaults` JSON literal landed in
  the engine. The auto-seeded `ems__Effort_plannedStartTimestamp = $today`
  default originally lived in the JSON literal.

- RFC v2 Phase 5 (exocortex#3167, 2026-05-23) — the legacy JSON-literal
  `propertyDefaults` parser was removed from the engine. The proper
  replacement is the ref-form `exocmd__Grounding_propertyDefault` (singular)
  → `exocmd__PropertyDefault` asset chain that vault-2025 adopted in
  Phase 4a (`c4e16484-…`). The starter-kit Phase 1 ontology bootstrap
  (DeclarativeRule, PropertyDefault, SubstitutionToken classes + the
  canonical-label-aligned property defs the ref-form parser requires) is
  out of scope for this minimal-impact fix; until it lands, this grounding
  ships **without** the auto-seeded `plannedStartTimestamp` default. Users
  can fill the field manually on the created task, or upgrade their vault
  to ref-form (see vault-2025 `assetspaces/exocmd/c4e16484-…md` for the
  reference shape).
